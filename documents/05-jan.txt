💡 JAWABAN PERTANYAAN ANDA:
1. STREAMING JSON PARSER - Apa Maksudnya?
Masalahnya:
// ❌ BAD: Load semua 10 MB ke memory sekaligus
response, err := http.Get(url)
body, _ := ioutil.ReadAll(response.Body) // Ini load 10 MB sekaligus!
json.Unmarshal(body, &result)            // Memory spike!

Solusinya:
// ✅ GOOD: Stream JSON satu per satu (tidak perlu ubah API)
response, err := http.Get(url)
decoder := json.NewDecoder(response.Body) // Stream dari HTTP body

// Read opening bracket
decoder.Token() // {

// Read "data_mutation" field
decoder.Token() // "data_mutation"

// Read array opening
decoder.Token() // [

// Loop untuk setiap record (1 by 1, bukan 400k sekaligus)
for decoder.More() {
    var record MutationRecord
    decoder.Decode(&record) // Decode 1 record aja
    
    // Langsung insert ke DB (batch 1000)
    batchRecords = append(batchRecords, record)
    if len(batchRecords) >= 1000 {
        db.CreateInBatches(batchRecords, 1000)
        batchRecords = nil // Clear memory
    }
}

euntungan:

✅ Memory usage tetap rendah (cuma butuh ~100 KB untuk 1000 records)
✅ Tidak ada perubahan di API (ini di sisi client/Go code aja)
✅ Bisa handle 10 MB, 100 MB, bahkan 1 GB response
✅ Lebih cepat karena insert parallel (read → insert → read → insert)
2. SHADOW TABLE STRUCTURE - Bedanya Apa?
OPSI 1: PURE JSON (Ide awal Anda)

CREATE TABLE mutation_cache (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  raw_data JSON,  -- Simpan seluruh response API
  updated_at TIMESTAMP
);

Cons:

❌ Query LAMBAT (harus parse JSON setiap kali query)
❌ Tidak bisa filter di SQL: WHERE seaman_code = '20040002' → harus load semua, parse JSON, filter di Go
❌ Tidak bisa sort: ORDER BY transaction_date DESC → tidak bisa
Query jadi:
// Harus load SEMUA data (400k rows), parse JSON, filter manual
var caches []MutationCache
db.Find(&caches) // Load 400k rows!

for _, cache := range caches {
    var mutations []Mutation
    json.Unmarshal([]byte(cache.RawData), &mutations)
    for _, m := range mutations {
        if m.SeamanCode == "20040002" { // Filter manual
            results = append(results, m)
        }
    }
}

OPSI 2: STRUCTURED + JSON BACKUP (Rekomendasi saya)

CREATE TABLE mutation_cache (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  seaman_code VARCHAR(50) NOT NULL,           -- ✅ Kolom biasa (fast query)
  transaction_date DATE NOT NULL,             -- ✅ Kolom biasa (sortable)
  from_vessel VARCHAR(255),                   -- ✅ Kolom biasa
  to_vessel VARCHAR(255),                     -- ✅ Kolom biasa
  from_rank VARCHAR(100),
  to_rank VARCHAR(100),
  jenis VARCHAR(100),
  raw_data JSON,                              -- ✅ Backup full data (jaga-jaga)
  updated_at TIMESTAMP,
  INDEX idx_seaman_date (seaman_code, transaction_date DESC)  -- ✅ Fast query
);

Pros:

✅ Query SUPER CEPAT dengan index
✅ Bisa filter langsung di SQL: WHERE seaman_code = '20040002'
✅ Bisa sort: ORDER BY transaction_date DESC LIMIT 10 (ambil 10 terakhir)
✅ Tetap ada raw_data JSON untuk backup (jika butuh field lain nanti)
Query jadi:
// Query langsung di DB (pakai index, super cepat)
var mutations []MutationCache
db.Where("seaman_code = ?", "20040002").
   Order("transaction_date DESC").
   Limit(10).
   Find(&mutations) // Dapat 10 rows aja, langsung dari index!

KESIMPULAN:

Opsi 2 lebih baik karena:

Simple & Effective Error Handling:

func (s *NanikaAPIService) FetchSeamenData() error {
    var lastErr error
    
    // 1. RETRY 3X (jika API error)
    for attempt := 1; attempt <= 3; attempt++ {
        s.Log.Infof("Fetching seamen data (attempt %d/3)...", attempt)
        
        response, err := s.callSeamenAPI()
        if err != nil {
            lastErr = err
            s.Log.Warnf("Attempt %d failed: %v", attempt, err)
            time.Sleep(5 * time.Second) // Wait before retry
            continue
        }
        
        // 2. SUCCESS → Update cache
        return s.updateSeamenCache(response)
    }
    
    // 3. ALL RETRIES FAILED → Log error & JANGAN overwrite data lama
    s.Log.Errorf("❌ Failed to fetch seamen data after 3 attempts: %v", lastErr)
    return fmt.Errorf("API error after 3 retries: %w", lastErr)
}

4 Hal Penting:

Retry 3x dengan delay 5 detik
Log setiap error dengan detail (untuk debugging)
Jangan overwrite data lama jika API gagal
Return error untuk cron job log (agar tahu ada masalah)
